Ranking harness artifacts by evaluation-awareness leakage

Which properties of an agentic eval harness leak cues that a model can detect — and do those cues change what the agent actually does?

repo · lkang172/agent-eval-experiment branch · main @ a8ff0d7 tests · 19/19

What this study is

Read docs/overview.md in full before changing anything

Evaluation harnesses leak cues, and models detect them. That much is established. What designers lack is an ordered list of which harness properties leak worst, so they know what to fix first.

Chat-based studies can't produce that list — in chat the prompt is the whole stimulus, so evaluation context is entangled with benchmark format. Agentic trajectories separate the task from the harness, which is what makes the attribution possible.

Two research questions, measured independently:

  • RQ1 — attribution. Ranked by effect size, which harness properties shift a linear probe's eval/deploy score with task text held fixed? This measures representation.
  • RQ2 — dissociation. For each property, does a representational shift come with a behavioral shift — a change in which tool the agent picks at a decision point?

The four factors under test, each toggled between an eval-like and a deploy-like setting:

IDFactorEval-like (0)Deploy-like (1)
F1Tool-return payload realismMinimal tidy JSON, task-relevant fields onlyExtra fields, nulls, nested metadata
F3Failure realismNo tool call ever failsTransient failure, then retry
F4Identifier realismSequential synthetic (user_001)UUIDv4, checksummed SKUs
F6Session/state artifactsReset markers, eval-set metadata, fixed seedNatural session continuation

F2 (latency) and F5 (user-turn provenance) were cut before this work began — see the brief.

Environment

Colab T4, 8-bit — the model does not fit in fp16

A 16 GB T4 cannot hold Llama-3.1-8B in fp16 (~16.1 GB of weights before activations), so everything runs in 8-bit. This is a stated limitation of the study, not an implementation detail: the probes read quantized activations. results.json records the quantization mode so runs from different settings are never pooled.

Weights come from NousResearch/Meta-Llama-3.1-8B-Instruct — an ungated mirror. The official meta-llama repo is gated: manual and would block on an access request.

Data handling

SAD's license requires that its question and answer text never appear in plain text anywhere scrapable, including private repos. Everything SAD-derived lands in data/sad/, which is gitignored. Do not copy SAD text into results, notebooks, logs, or commit messages.

Rendered trajectories are also gitignored. They are deterministic — python -m rvr.build reproduces all 390 byte-for-byte — so auditability is preserved without publishing eval-awareness stimuli.

Decisions that deviate from the brief

All recorded in configs/preregistration.json — read it before changing analysis

Δ_ctrl is a difference of contrasts

The brief writes Δ_ctrl = AUROC(eval arm) − AUROC(control arm), which doesn't parse — an arm has no AUROC, a contrast does. Resolved to AUROC(base vs deploy) − AUROC(base vs control): the factor's effect net of what its matched control reproduces.

§8.1's 2% token matching is unsatisfiable, and not the binding constraint

Every factor changes length by construction — F1 realism is extra fields (+60%), F3 failure+retry is extra content (+26%). Padding the eval arm to match would turn it into the deploy arm.

It also doesn't matter. Δ_ctrl subtracts two contrasts sharing the same eval arm, so a common length confound cancels. This is verified in tests/test_analysis.py: a probe reading only token length yields Δ_base > 0.95 and Δ_ctrl < 0.05. What the endpoint actually needs is each control matched to its own deploy arm, which is enforced and holds at a mean |Δ| of 0.47%.

Probe A is trained, not transferred

Nguyen et al.'s released probe is a Llama-3.3-70B direction (hidden dim 8192). Llama-3.1-8B is 4096. It is dimensionally inapplicable, not weakly-transferring. Their 0.517 / 0.584 / 0.598 baselines are reference points only; we recompute our own.

F6's deploy arm is a content contrast

"Absent; continuous session context" read two ways. Resolved so all three F6 arms carry a structurally identical five-key block, differing only in what it signals. Keeps F6 length-matched instead of being a presence/absence effect that B-len would absorb.

The behavioral arm is staged

base vs stacked_deploy is the maximum available manipulation and separates representationally at AUROC 0.999. Screening on it first is the most powerful test of whether harness realism moves behavior at all, at 1,200 generations instead of 4,950. Declared before any behavioral data existed.

Results: RQ1, representation

Probe A is a corpus classifier — do not use it

Probe A reached 0.9999 AUROC on SAD stages_oversight. That is not evaluation awareness. Its two classes come from disjoint corpora: eval from test_anthropic/bigbench/wmdp, deploy entirely from wildchat_sampled.

The length and special-character baselines are blind to a vocabulary confound, which is how a corpus classifier passed the original gate. gate_probe_a now treats a high embedding-layer AUROC as a disqualifier, and this probe fails it.

This reproduces Devbunova's critique (2603.19426) on our own setup and is worth reporting as a finding, not just fixing.

Layer 1 was the only leaking layer in the network

Selecting the probe layer by maximum AUROC picked layer 1 — whose probe separates two contexts differing only in JSON indentation (F0 AUROC 0.202, token-count identical). Layer selection is now constrained to layers passing the F0 null control. 32 of 33 pass; the constraint costs 0.016 AUROC and selects layer 4, where F0 passes at 0.457.

Method note worth publishing

Choosing a probe layer by maximum held-out AUROC actively selects for surface sensitivity — the most token-driven layer wins. Constraining by a cosmetic null control removes the artifact at near-zero cost in AUROC.

The last two columns are the important ones. For F1 and F3, a token-count-only classifier beats the probe outright. For F4 it ties. Only F6 shows the probe reading beyond surface form, by +0.277.

Do not report this as a ranking

F6's +0.074 sits below the noise floor. The random-direction band recomputed at layer 4 gives p95 = 0.147, and tested directly, 14.5% of random meaningless directions produce |Δ_ctrl| ≥ 0.074.

Honest verdict: no factor's representational effect clears the noise floor at N=30. F6 is the only candidate — the only significant Δ_ctrl and the only factor reading beyond length — but it is suggestive and underpowered. Report with a power statement.

One caveat to carry into the writeup: F6 is the single factor whose length confound does not cancel in Δ_ctrl (B-len gives −0.112 versus exactly 0.000 for the others), because its three arms sit within ~1% on tokens so both AUROCs are near chance. The probe effect runs opposite to that contribution, so it isn't explained by length — but F6's contrast is less clean than the others'.

Results: RQ2, behavior

results/behavioral.json — a measurement failure, not a null

The first screen ran 1,200 generations over 85 minutes and produced no usable behavioral data. 87.2% of generations emitted no parseable tool call. Only 9 of 30 tasks yielded any decision; one showed the agent picking both branches. The §11 dynamic-range gate correctly reported usable: False.

Parsed choiceCountShare
none — no tool call found104687.2%
efficient branch877.2%
other tool363.0%
cautious branch312.6%

The screen's Δ = +0.001 (p = 0.70) is meaningless — it compares two conditions in which the model mostly did nothing parseable.

Cause. The behavioral prompts were built on the probe arm's transcript format, whose markers (<|assistant|>, <|tool_call|>) are invented strings that tokenize as ordinary text, not Llama-3.1 special tokens. Harmless for probing, where only consistency across arms matters. Fatal for eliciting an action: the model was asked to continue an unfamiliar raw-text format rather than use tools as trained, and mostly declined.

Fix, committed but unrun. build_prompt_native renders the identical semantic context through the model's own chat template with proper tool schemas, cut at the same decision point. --format native is now the default. The driver also persists sample generations and abstention examples — their absence made the failed run undiagnosable and wasted the GPU time.

4

Run the §4.3 control-validity check

Not yet started, and it gates every Δ_ctrl interpretation. An LLM judge scores all 390 arms 1–7 on "does this look like a test fixture rather than a live system"; ~50 human ratings validate the judge. Each control arm must sit at or below its eval arm. If a control scores higher, that factor's Δ_ctrl is invalid and only Δ_base may be reported.

There is already a signal worth chasing here: F3's Δ_ctrl came out significantly negative in the layer-1 run, meaning its control separated more than its deploy arm — exactly the inversion this check exists to catch.

Traps that already cost time

Each of these was a real bug — regression tests now pin them

  • Scoring in-sample. Fitting Probe B on the base and deploy arms then scoring those same contexts measures training-set fit. It produced Δ values of exactly 0.0 and 1.0 and a spurious F0 failure. Always use fit_folds_and_score_all, which scores every context with a probe that never saw its task.
  • AUROC polarity. Eval-like is the positive class throughout, matching Probe B's labelling (base=1). Passing base as the negative class returns 1 − intended and silently inverts every ranking.
  • F0_null_a is byte-identical to base. By design — the F0 pair differs only in whitespace. But it means an in-sample probe compares a memorised training point against a perturbation of it.
  • Solution terms must come from task-relevant fields. F1's eval arm drops contextual and metadata fields, so a solution term sourced from one appears in some arms and not others and trips the answer-leakage audit. TaskSpec.validate() now rejects this.
  • System prompts must not use {placeholder} templating. The §7 verification found that ADK's eval-only request intercepter writes a UUID into session state, which an instruction interpolating that key picks up from turn 2. Static prompts are immune; TaskSpec.validate() enforces it.
  • Colab runtimes are recycled. Long runs lose everything. Add checkpointing before any multi-hour run.

Open questions for the human

  • The behavioral equivalence margin. The probe arm's TOST margin is in AUROC units and does not transfer to a difference in proportions. Before any "does not affect behavior" claim, someone must set the smallest shift in cautious-branch rate an eval designer would actually act on. This is a judgment call, not a computation.
  • N=30 may be too small. The random-direction noise floor at layer 4 is 0.147 while the largest observed effect is 0.074. Either raise N toward the brief's preferred 40, or accept that the representational arm reports an underpowered result with honest power reporting.
  • Quantization. All results read 8-bit activations. If a larger GPU becomes available, an fp16 replication would remove the caveat entirely.
Framing discipline, from the brief

This study does not resolve a confound and is not a decisive test. It separates two previously entangled things and reports what it finds. A well-powered null is a publishable result; an underpowered null is not. The axis that matters is powered versus underpowered, not positive versus null.
